# 《不/存在的莉莉丝》无障碍补丁 · 常见问题

补丁版本 `0.1.0`｜Steam AppID **4643090**｜Unity 2021.3.45f2c1 / IL2CPP｜BepInEx **6.0.0-be.788**

装法、按键、每一项配置是什么意思，看 [安装说明.md](安装说明.md)。
哪些地方还没实机验证，看仓库里的 `docs\TODO-待验证.md`。

**这个补丁是玩家自制的第三方工具，与游戏作者没有任何关系，也没有得到授权或背书。
请通过 Steam 购买正版后再使用。**

> **先说最容易误会的一条：这个补丁默认不朗读台词。**
> 本作台词**全程有配音**，读屏用户只需要界面与控制，台词交给游戏语音。
> 补丁负责的是：**界面导航 + 控件朗读 + 选项朗读 + 数字键选择**。
> 想让它念无配音行，得手动打开 `[朗读] 朗读无配音剧情`（效果尚未逐句核对）。

## 装之前

### 我到底该往哪儿拷？

拷进**有 `Lilith.exe` 的那一层**，不是拷进 `Lilith_Data\`，也不是拷到 Steam 库根目录。
不确定的话：Steam 里右键游戏 → 管理 → 浏览本地文件，打开的就是那一层。

### 拷完游戏打不开了 / 一直卡在启动画面

先看是不是**只拷了一部分**：`winhttp.dll`、`doorstop_config.ini`、`.doorstop_version`、
`baselib.dll`、`BepInEx\`、`dotnet\` 必须齐全，缺一个 BepInEx 就起不来。
其次看是不是**装了两套 BepInEx**（比如以前装过别的模组）。
实在不行就把上面这些全删掉，确认游戏能正常启动，再重新拷一次。

### 第一次启动特别慢，是卡死了吗？

不是。BepInEx 第一次运行要按本机游戏生成 `BepInEx\interop\` 和 `BepInEx\unity-libs\`
（几百个文件），慢几分钟很正常。**只有第一次**慢。

### 补丁会改游戏文件吗？会不会被 Steam 判定篡改？

**不改。** 所有新增文件都在游戏根目录旁边，游戏本体一个字节都没动。
补丁也不联网、不写游戏资源。卸载就是删掉新增的那些文件（清单位于安装说明.md）。

## 装之后

### 一点声音都没有

1. **NVDA 开着吗？** 补丁不会替你启动读屏软件，它只是把话交给 NVDA。
2. 看 `<游戏目录>\BepInEx\LogOutput.log` 开头几行，应该有
   `语音后端就绪: …` 或 `语音不可用: …`。
   - 写「语音不可用」：后面会跟每个后端的失败原因。
   - 写「语音后端就绪: SAPI」但你听不见：系统可能没装中文语音
     （设置 → 时间和语言 → 语音）。
3. 一条都没有？那说明插件根本没加载：
   - 有没有那句「无障碍补丁已加载」？
   - 日志里有没有 `JustLilithA11y` 这个名字？
   - 有没有一行 `version is invalid`（版本号写坏会导致插件被整个跳过，
     本仓库的构建脚本有守卫挡这个，但手改过的构建产物可能中招）。

### 进剧情了，一句话都不读

**这是本作的默认设计，不是故障。** 台词全程有配音，交给游戏语音念，
补丁不重复朗读（`[朗读] 朗读无配音剧情` 与 `无法判定时也朗读` 默认都关）。
补丁负责的是界面：**导航、控件朗读、选项朗读与数字键**。
想让它念没有配音的行，把这两项打开，重启游戏再试。

### 有人的名字念成「未知」/ 念成内部 ID

如果补丁拿不到名字，它**不会猜**。名字本身可能就是剧情伏笔，
替作者抖包袱不是补丁该干的事。
名字来源是 `DialogueNode.speaker` 字符串，**实际值是不是中文名还没有核对**；
如果发现念的是内部 ID，把 `[朗读] 朗读时带上说话人` 关掉即可。

### 选项出来了，但没念 / 数字键没反应

1. 确认配置里 `[朗读] 朗读选项` 和 `数字键选择选项` 都是开的。
2. 数字键只在**当前确实有待选列表**时才吃（1–9），其余时候不拦；
   焦点在输入框里时也不抢数字键（为了能正常打字）。
3. 还是不行就把 `[其它] 界面诊断日志` 打开，重启，复现一次，
   把日志里 `[Choices]` 开头的几行发给我们。

### 菜单里按方向键没反应

1. 先**进入导航模式**：默认是 **`Ctrl+Alt+Plus`**
   （主键盘加号，= `Ctrl+Alt+Shift+=`；小键盘加号不算）。
   `Tab` 作为兜底仍然生效。
2. 如果按了没反应，检查配置里 `[界面导航] 导航开关快捷键` 是不是被改过、
   `快捷键全局生效` 是不是被关掉了——本作窗口拿不到键盘焦点，**这一项必须开**。
3. 进去了还是没反应：把 `[其它] 界面诊断日志` 打开，重启，进一次菜单，退出，
   把 `LogOutput.log` 里 `[诊断]` 的行发给我们。

### 按了方向键，游戏里的角色反而动了 / 剧情跳了

说明导航没有拦住游戏自己的按键。这是需要修的问题，不是设计。
记下当时在哪个界面（标题菜单 / 设置 / 剧情中），连同日志一起反馈。
（另：导航中**不静默游戏自带的热键**——本作输入走 native，没有可拦的托管入口，
这是已知取舍。）

### 生日那一行：按下开关只是展开日历；日历格念「14，按钮」

已知不足。生日行的 `SwitchBtn` 是**展开器**，不是开关；
「生日」行的状态语义还没修好，展开后的日历格 `DateCell` 只念「14，按钮」，
**没有「14 日」这样的日期语义**。记下读到的原文反馈，比笼统说「不对」有用。

### 「你的名字」那一行念成「你的名字，按钮」

已知不足。「我」tab 里的 `Btn_FolderSelect` 被上方行标题覆盖了，
它真实含义是「选择文件夹」（同一个控件在「声音」tab 里读法是对的）。

### 按空格推进剧情，结果把刚才点过的按钮又点了一次

这是 uGUI 的 submit 通路问题，只有当游戏自己也在用
`SetSelectedGameObject` / 选中态时才会发作。
本作要不要**常驻**关掉 `EventSystem.sendNavigationEvents` 仍在判定中，
见 `docs\TODO-待验证.md`。遇到时记下界面与操作顺序。

### 黑窗口跑出来了

那是 BepInEx 自己的日志窗口。本补丁没有「隐藏控制台窗口」这一项。
想彻底关掉：`BepInEx\config\BepInEx.cfg` → `[Logging.Console]` → `Enabled = false`。
日志文件照常写在 `BepInEx\LogOutput.log`。

### 游戏更新之后补丁没用了

游戏更新会换掉 `GameAssembly.dll`，interop 与补丁点可能一起失效。
删掉 `BepInEx\interop\` 让 BepInEx 重新生成，然后等补丁更新。
**别在游戏刚更新时到处试**，先确认原版能正常启动。

## 关于存档与隐私

### 存档在哪儿？

Unity 游戏一般存在：

```
%USERPROFILE%\AppData\LocalLow\<公司名>\<游戏名>\
```

**本作的确切路径还没有实查**（见 `docs\TODO-待验证.md`）。改配置、装补丁**都不碰存档**，
但你自己做实验前建议整个目录备份。

### 日志里会有我还没玩到的剧情吗？

**会。** `BepInEx\LogOutput.log` 可能含台词原文（例如诊断日志、台词判定日志）。
所以：**要发日志给我们时，请先确认里面有没有你不想被公开的内容**；
我们这边也有纪律——含台词原文的日志不入库、不公开。
如果你只想报告「有没有声音」，可以只发开头的后端初始化那几行。

### 这补丁算作弊吗？

它**只加朗读和键盘操作**，不改剧情、不改数值、不跳过内容、不替你选分支。
选项朗读与数字键只做「替你按了那一个按钮」，不删选项、不碰任何计时。
如果哪天有人拿它当外挂用，那是那个人违规，不是补丁的设计意图。

## 反馈

发问题请带三样东西：

1. **`BepInEx\LogOutput.log`**（先自己看一眼有没有不想公开的台词）；
2. **`测试问卷.md` 里对应那一节**，没复测的写「尚未实机复测」；
3. 你在哪个界面、按了什么、期望听到什么、实际听到了什么。

只有一句「不好使」是没法定位的。
