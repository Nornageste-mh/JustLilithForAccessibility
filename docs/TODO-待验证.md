## A. 阻塞代码的（不解决就写不出补丁点）

### [x] A1. 导航模式键位 —— 最终定为 `Ctrl+Alt+Plus`

- **结论**：`Ctrl+Alt+Plus`（主键盘加号 = `Ctrl+Alt+Shift+=`），`Tab` 作为兜底仍生效。
- **为什么不选纯 `Ctrl+Alt`**：本作自带 **9 条 `Ctrl+Alt+字母` 热键**
  （`Ctrl+Alt+L` 强制点击穿透、`Ctrl+Alt+S` 静音、`Ctrl+Alt+N` 随手记、
  `Ctrl+Alt+B` 详细备忘、`Ctrl+Alt+R` 提醒事项、`Ctrl+Alt+P` 番茄钟、
  `Ctrl+Alt+T` 计时、`Ctrl+Alt+K` 闹钟、`Ctrl+Alt+M` 音乐播放器），纯 `Ctrl+Alt` 会冲突；
  加号不在游戏热键表里，且主键盘 `=` 上的加号要多按一个 `Shift`，误触概率最低。
- **实现位置**：逐作层 `mod\src\JustLilithA11y\Plugin.cs:195`
  （`Config.Bind("界面导航", "导航开关快捷键", "Ctrl+Alt+Plus", …)`）、
  `Plugin.cs:535` 的 `NavTogglePressed()`；平台层 `UiNav.cs:2160-2161`
  （`navHook != null ? navHook() : KeyEdge.Pressed(KeyCode.Tab)`，钩子没填才退回 `Tab`）。
- **证据**：2026-10-22 实机，按 `Ctrl+Alt+Plus` 能进 / 出导航模式并逐项朗读设置面板；
  退出导航后按游戏自带 `Ctrl+Alt+M` 正常打开音乐播放器（不抢键）。
- **解锁**：文档键位表去掉「待实现」标注（README / 安装说明 / 常见问题已改）。
- **0.2.0 补充**：普通状态下「进了导航没东西可走」不是键的问题（见 F1），
  另加了 `Ctrl+Alt+O` 叫出功能菜单（见 F2）；导航键本身不变。

## F. 0.2.0 新增功能（2026-10-23）

### [x] F1. 「普通状态进不了导航」的根因

- **结论**：不是导航键失效。平台层只扫**当前场景里看得见**的 `Selectable`，
  而游戏平时不显示功能菜单，于是导航模式「进去了却没有可走的东西」，听感上等于没反应。
- **证据**：2026-10-22 实机（导航键本身可用：设置面板打开时可逐项走）+ 0.2.0 用户反馈。
- **对策**：0.2.0 加 `Ctrl+Alt+O` 叫出功能菜单（F2）+ 菜单常驻（F5）。
- **仍缺**：这条根因没有单独的日志证词，依据是用户描述 + 平台层实现阅读。

### [~] F2. `Ctrl+Alt+O` 打开 / 关闭游戏功能菜单

- **现状**：`LilithMenu.cs` 实现；开 = `LilithApi.OpenMenu()`（先
  `CharacterController.ToggleSetting()`，失败退 `SettingView.Show()`），
  关 = `CloseMenu()`；可见判据 `_canvasGroup.alpha > 0.5`；开、关各念一句。
- **仍缺**：连续开关、与游戏自带 9 条热键同时按下、开着菜单进对话时的行为，
  都没有逐项实测；`O` 是否被别的输入路径占用也未核对。
- **由谁验证**：Lead / 测试者。
- **解锁**：文档里 `Ctrl+Alt+O` 从「已实现」升到「已实机验证」。

### [~] F3. 身体部位导航 8 项（头 / 脸 / 胸口 / 身体 / 左手 / 右手 / 裙子 / 腿）

- **已有证据（2026-10-23 实机）**：部位命中区被正确派发
  （`Head` / `Chest` / `Hand` / `Skirt`），语音 clip 由 `2100110_cn` 变成 `2051236_cn`。
  另一次记录：只调 `DelayedSingleClick(area, anchor)` 游戏**没有任何可观测反应**，
  改成 `HandleMouseDown()` + `HandleMouseUp()` 之后才真触发对话
  （`OnDialogueStart lineId=2100109`）。
- **结论**：实现是「光标就位 + 走游戏原生点击链路」，不是模拟 UI 事件；
  1.5 秒兜底判据 = 出新台词或 voice clip 变化。
- **仍缺**：8 个部位**逐个**的反应（音效 / 动画 / 台词、会不会被相邻碰撞体抢走）；
  导航里切到「莉莉丝交互」后上下移动的实机确认。
- **由谁验证**：用户试听 + `[Lilith]` 诊断日志（锚点 / 屏幕坐标 / 部位交互成功 / 兜底提示）。

### [ ] F4. 身体部位交互反馈的实机确认（用户试听 / 试看）

- **需要什么证据**：一位真人在游戏里对每个部位各按 3 次回车，逐项记下：
  有没有声音（音效 / 台词 / 语音）、有没有动画、导航念的是有反应还是「没有反应」，
  并附 `[BodyPart]` 开头的日志行。
  **这项必须由人来做**：自动化只能判定「有没有新台词 / clip 变没变」，判不了听感与观感。
- **由谁验证**：用户 / 测试者（照 `测试问卷.md` 的「身体部位」一节）。
- **解锁**：README 与安装说明里「部位反应由游戏决定」可以具体到每个部位；
  若某些部位确实没反应，考虑从导航里摘掉或在文档里点名。

### [~] F5. 菜单常驻（`功能菜单不自动隐藏` / `对话气泡不自动消失`）

- **现状**：功能菜单保活 = 只在补丁打开期间重开，对话开始即停（冷却 1.5 秒、上限 500 次）；
  气泡常驻 = 显示期间周期性把计时器重置回原值，不改流程。
- **已有证据**：配置项与实现路径存在（`Reader.cs:133-140`、`Choices.cs:113` 有注释）；
  未逐项实测。
- **仍缺**：长剧情里的观感、会不会盖住对话界面、气泡重置有没有副作用；
  「玩家主动关掉后又被重开」的实际频率。
- **由谁验证**：测试者。
