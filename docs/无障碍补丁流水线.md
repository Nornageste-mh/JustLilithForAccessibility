## 0. 结论先行

### 0.1 三作的共同点（一句话）

**它们是同一套代码的三次「复制—改名—局部改写」，而不是三个独立项目。**

- 平台层（语音朗读 + 界面导航）三作几乎逐字节相同，差异只有 `namespace` 一行；
- 逐作真正改写的只有 **文本清洗规则** 和 **Harmony 补丁点**；
- 三作共用同一套构建 / 探针 / 打包 / 合规 / 文档骨架；
- 因此**共性不是「设计得像」，而是「事实上就是同一份」** —— 可以直接固化成模板。

### 0.2 最关键的三个数字

| 指标 | 数值 | 含义 |
|---|---|---|
| 平台层规模 | **约 2130–2390 行**（Speech + Sapi + Nvda + UiNav） | 这部分可以整份复用，不重写 |
| `Sapi.cs` / `Nvda.cs` / `Speech.cs` 三作差异 | **0 / 1 / 3–10 行**（前两者的差异只有 `namespace`） | 已是事实上的冻结层 |
| `Plugin.<成员>` 跨文件引用 | **63 / 117 / 64 处**，散在 4–9 个文件 | ABI 未固化，是复用的唯一真实摩擦 |

### 0.3 本流水线的核心主张

> **把平台层与逐作代码之间的接口（ABI）固化成一层显式的 `A11yHost` 契约。
> 契约一旦固化，平台层逐字节复用；不固化，每作都要重做 63–117 处改名 + 人工回归。**

这是本文档唯一要求「新增设计」的地方，其余全部是既有实践的固化。

## 2. 架构：三层

```
┌──────────────────────────────────────────────────────────┐
│ L1 平台层（逐字节复用，永不逐作改写）                      │
│   Speech.cs  后端链 Tolk→NVDA→争渡→SAPI + 定期重试        │
│   Nvda.cs    nvdaControllerClient.dll 探测与朗读          │
│   Zdsr.cs    争渡读屏 ZDSRAPI（运行时按目录加载）          │
│   Sapi.cs    纯 P/Invoke + vtable 的 ISpVoice             │
│   UiNav.cs   Unity Selectable 通用导航引擎                │
├──────────────────────────────────────────────────────────┤
│ L2 契约层（每作一个薄适配文件，固化 ABI）                  │
│   A11yHost.cs  共享层唯一可见的宿主（配置 + 日志 + 钩子）  │
│   Plugin.cs    BepInEx 入口：注册配置、注册补丁             │
├──────────────────────────────────────────────────────────┤
│ L3 逐作层（真正的开发工作量所在）                          │
│   TextProc.cs     原始文本 → 可朗读文本（本作专属规则）    │
│   Patches/*.cs    Harmony 补丁点（按反编译实查的方法名）   │
│   Choices/Qte/…   本作特有的交互形态                      │
└──────────────────────────────────────────────────────────┘
```

### 2.1 L1 平台层的复用边界（精确到成员）

**`Speech.cs`** — 语音输出抽象层。

```
公开接口（全部静态）：
  Backend Current                 当前后端枚举 None/Tolk/Nvda/Zdsr/Sapi
  string  BackendName             可朗读的后端名（含 Tolk 探测到的读屏名）
  bool    TolkHasBraille          盲文可用性
  void    Init(ManualLogSource)   按优先级挑选第一个可用后端
  bool    Ready()                 不可用时每 10s 重试（NVDA 可能后启动）
  void    Speak(string, bool)     朗读；interrupt 决定是否打断
  string  CycleAvailable()        运行中切到下一个可用后端（0.2.0.0），返回播报文本
  void    Stop()                  停止
  void    Shutdown()              Tolk_Unload + Sapi.Shutdown
```

关键设计（**照抄，不要重新发明**）：

- 自带 NVDA / 争渡 / SAPI 三级，**不强依赖 Tolk**（维护分支 `ndarilek/tolk` 有 CI 构建的 `tolk.zip`，但无版本 tag、只有 `master`；
  Tolk 是 **LGPL-3.0**，随包须附许可全文。且 JAWS/SuperNova/ZoomText 分支无法验证）。
- 争渡这一级的可用性判据**只能是** `GetSpeakState() ∈ {3,4}`：未授权时 `Speak()` 也返回 0，
  拿返回值当判据就是「日志一片绿、耳朵一片安静」（0.2.0.0 的 `Zdsr.cs`）。
- 后端选择可被配置钉死（排查用）；**钉死后不可用不会回退**，这是刻意的。
- 初始化失败时把每个后端的结论串成一行日志（`Verdict()`），一眼看出「为什么全灭」。
- 朗读抛异常 → 后端降级为 `None` 并允许重试，绝不把异常抛给游戏主循环。

**`Sapi.cs`** — Windows 内置语音，**纯 P/Invoke**。

> **绝不要用** `Type.GetTypeFromProgID("SAPI.SpVoice")` + `InvokeMember`。
> Unity 的 Mono **没有实现** COM 后期绑定，实机日志是
> `SAPI 不可用: NotImplementedException`，表现是整局游戏一片安静。

已实机验证的 vtable 槽位（照抄，错一位就会当场露馅）：

```
0  QueryInterface        1  AddRef              2  Release
3  SetNotifySink         4  SetNotifyWindowMessage
7  SetNotifyWin32Event   10 SetInterest         11 GetEvents
16 Pause                 17 Resume              18 SetVoice
20 Speak                 21 SpeakStream         22 GetStatus
28 SetRate               29 GetRate             30 SetVolume
31 GetVolume             32 WaitUntilDone       33 SetSyncSpeakTimeout
```

- `CLSID_SpVoice = 96749377-3391-11d2-9ee3-00c04f797396`
- `IID_ISpVoice  = 6c44df74-72b9-4992-a1ec-ef996e0422d4`
- `COINIT_APARTMENTTHREADED = 0x2`，`CLSCTX_ALL = 0x17`
- **`SPF_ASYNC = 1` 必须置位**：SAPI 默认同步朗读，会阻塞 Unity 主线程导致游戏卡死。
- `Stop()` = `Speak(NULL, SPF_ASYNC | SPF_PURGEBEFORESPEAK)`（`SPF_PURGEBEFORESPEAK = 2`）。
- 初始化时**先读 rate/volume 验证 vtable 槽位**（错了在这一行露馅，而不是等玩家需要朗读时静默失败）。

**`UiNav.cs`** — 通用导航引擎，**几乎不引用任何游戏类型**。

belfry / transparenther 引用的类型只有 UnityEngine 系：

```
UnityEngine.EventSystems · UnityEngine.Object · UnityEngine.SceneManagement
UnityEngine.UI · UnityEngine.UI.Text · (TMP)
```

引擎机制（照抄）：

| 机制 | 实现 |
|---|---|
| 控件发现 | 每帧扫描 `Selectable`（**不依赖游戏提供任何列表**） |
| 分组 | 按控件在 Canvas 下的**顶层祖先**分组；组间按 `CanvasOrder → SiblingIndex` |
| 组内排序 | `ItemKey` 字典序：**Row（屏幕上下）→ Left（屏幕左右）→ Path（渲染层级）** |
| 重扫 | **只扫「下一帧」**，且加**场景稳定门禁**（`SceneStable` / `SceneSettleSeconds = 1.5f`） |
| 位置换算 | `WorldToScreenPoint` 后再分档（世界坐标 ≠ 屏幕像素） |
| 可见性 | `VisiblyClickable` + `CanvasGroup.alpha` |
| 退出确认 | `QuitConfirmArmed` / `QuitConfirmSeconds = 8f` |
| 危险操作 | `NeedsQuitConfirm` + `CfgQuitNames` |
| 输入角色 | `InputFieldRoleName` / `SliderValueText` / `PlaceholderText` |

> **绝不要对 `List.Sort` 的比较函数用「近似相等」当分支**（如 `Mathf.Abs(a.Left-b.Left) > 0.01f`）。
> 它不满足传递性，内省排序的结果是**任意的**，而且**不报错**。必须严格字典序。

### 2.2 L2 契约层：固化 ABI（**本流水线唯一的新增设计**）

**问题**：共享层目前直接读 `Plugin.xxx`，导致三作命名漂移、每作要改 63–117 处。

**方案**：新增 `A11yHost.cs`，作为**共享层唯一允许引用的宿主**。

```csharp
// A11yHost.cs —— 每作一份，只填值，不写逻辑
internal static class A11yHost
{
    // ---- 日志（共享层唯一日志出口）----
    internal static ManualLogSource Log;
    internal static bool DiagOn;                 // 「界面诊断日志」总开关
    internal static void Diag(string msg) {      // 统一诊断出口，带 [UiNav]/[朗读] 前缀
        if (!DiagOn || Log == null) return;
        try { Log.LogInfo(msg); } catch { }
    }

    // ---- 共享层需要的配置（名字固定，语义固定）----
    internal static ConfigEntry<string> CfgSpeechBackend;   // 自动/Tolk/NVDA/争渡/SAPI
    internal static ConfigEntry<bool>   CfgDiagLog;         // 朗读诊断日志
    internal static ConfigEntry<bool>   CfgVisibleOnly;     // 导航只含可见控件
    internal static ConfigEntry<bool>   CfgSortByPosition;  // 按屏幕位置排序
    internal static ConfigEntry<string> CfgExcludeNames;    // 人工排除名单（逗号分隔）
    internal static ConfigEntry<bool>   CfgQuitConfirm;     // 退出二次确认
    internal static ConfigEntry<string> CfgQuitNames;       // 需确认的控件名

    // ---- 共享层需要的钩子（由各作 Plugin/Patches 实现）----
    internal static Func<bool> BlockGameAdvance;  // 导航模式下是否拦截「推进剧情」
    internal static Action      TickUiNav;        // Plugin.Update 每帧调用（含 KeepUnitySubmitOff）
}
```

**迁移成本（已实测）**：只需把共享层里的
`Plugin.Log` / `Plugin.CfgXxx` / `Plugin.Diag` 改指 `A11yHost.*`，
并让各作 `Plugin.cs` 在 `Awake/Load` 里填一次值。三作合计 244 处引用、19 个文件要过一遍，
但**这是最后一次**：之后新作只需照抄 `A11yHost.cs` 填空。

**共享层绝不允许引用的东西**（一旦引用就丧失复用性）：

- 任何游戏类型（`DialogueScene` / `Naninovel.*` / `PhoneDialogueManager` …）
- 任何逐作配置项（`CfgReadUnvoiced` / `CfgSilenceKey` / `CfgChoiceHotkeys` …）
- `Il2CppInterop` / `Il2CppSystem`（IL2CPP 路线的特化处理留在逐作层）

### 2.3 L3 逐作层：真正的工作量

#### (a) `TextProc.cs` —— 文本清洗（**每作必须重写**）

这是「同一作内所有花括号都在这里」的地方。各作要处理的类别完全不同：

| 类别 | 《钟塔》 | 《不/存在的你，和我》 | 《透明的她与真实的我》 |
|---|---|---|---|
| 说话人包装 | `【 角色A 】` 全角方括号 + 空格 → 剥掉 | — | — |
| 遮蔽名 | `【 ?  ? 】` → 念「？？？」 | — | — |
| 多人同框 | `【 角色B/角色A 】` → 斜杠念成顿号 | — | — |
| 富文本 ruby | — | `<ruby="注">正文</ruby>`（**正文与旁注都要读**，本作题眼） | — |
| 抹除符号 | — | `█ ■ □` → 念「方块」 | — |
| 行内注释 | — | `;; @wait 2` 之后不朗读 | — |
| 正则 | `NameBracketRe / SpaceRe / MaskRe` | `RubyRe / TagRe / BlockRe / CommentRe` | 并入 `Plugin.Reader.Clean()` |

> **ruby 那条是硬要求**：《不/存在的你，和我》的设计是「正文=表象、旁注=真相」，
> **只读正文会让盲人玩家错过题眼**。这不是优化，是无障碍完整性问题。

#### (b) 补丁点 —— Harmony 挂载（**每作必须重查**）

| 抓换行/继续 | `ShoushuDialoguePresenter.PresentLineAsync` | — | `Ending2DialogueManager.StartTyping` |
| 选项出现 | `ChoiceHandler.ExecuteSelectionLogic` / `ExecuteRealTimeLogic` | `GenerateSelectionButton` / `GenerateReplyButton` | `DialogueSceneManager.ExecuteSelectionLogic` |
| 限时选择延长 | `ChoiceHandler.AutoDestroyAfterTime`（**只改 `ref delay`**） | （同） | `AutoDestroyAfterTime(ref float, DialogueScene)` |
| 手机消息 | `PhoneDialogueManager.AddMessage` | — | `PhoneDialogueManager.AddMessage(string,bool,PhoneDialogue)` |
| 手机选项 | `PhoneDialogueManager.HandleChoiceMessages` | — | `PhoneDialogueManager.HandleChoiceMessages` |
| 手机贴纸 | `HandleExpressionMessage` | — | `HandleExpressionMessage(PhoneDialogue)` |

| （本作特有） | — | QTE：`QTEUI` / `QTEScoreComponent` / `QTEButton` | 倒计时进度条 `FadingSlider.FadeSliderOverTime` |

**挂载点的唯一权威来源**：反编译实查（`ilspycmd`）+ 探针场景树转储。**不许猜方法名、不许猜对象名。**

#### (c) 别名表 —— 每一条都必须有依据

`UiNav` 的 `NameAlias`（对象名 → 中文）是逐作表，且**注释里必须写明依据**。
belfry 的写法是范例：

```csharp
// 标题旋转菜单的五个按钮，名字与动作的对应是从
// ClockwiseMenuController.Awake 里实查的：
//   SetButtonAction(0, handler.QuitGame) …
// 对象名则是 probe 的场景树转储里实查的：
//   Canvas/Panel/Background/Menu/Buttons 下依次是
//   Gallery / Load / Start / Options / Exit。
```

> 源码注释原文：**「每一条都要有依据，不要凭感觉往里加：」**
> 这条纪律要继承。

## 3. 第一条硬约束：选技术栈路线

**这是新作的第 0 个决策，决定后续一切。**

| | **Mono 路线** | **IL2CPP 路线** |
|---|---|---|
| 参考实现 | TransparentHer（v0.5.9.0）、belfry | noexistence |
| BepInEx | **5.4.23.5** | **6.0.0-be.788** |
| 插件入口 | `BaseUnityPlugin` | `BasePlugin` |
| TFM | `netstandard2.1` | `net6.0` |
| 引用来源 | `<游戏目录>\<Game>_Data\Managed\*.dll` | `<游戏目录>\BepInEx\interop\*.dll` |
| 参考 BepInEx 程序集 | `bep_dl\BepInEx\core\BepInEx.dll`（构建脚本自下） | `<GameDir>\BepInEx\core\BepInEx.Core.dll` 等 |
| 前置条件 | 无（直接读 Managed） | **必须先装 BepInEx 6 并跑一次游戏**，生成 `BepInEx\interop\` |
| 额外配置 | — | `AllowUnsafeBlocks` + `<CodePage>65001</CodePage>` + 可能需要打过补丁的 `Il2CppInterop.Runtime.dll`（上游 PR #277） |
| 危险点 | 较少 | **三类「静默失败」**，见 §4.2 |

**判定方法**：看游戏目录里是 `<Game>_Data\Managed\Assembly-CSharp.dll`（Mono）
还是 `<Game>_Data\il2cpp_data` + `GameAssembly.dll`（IL2CPP）。

> 两作 Mono 的 csproj 都**必须**有可复现构建三行：
> `<Deterministic>true</Deterministic>` +
> `<IncludeSourceRevisionInInformationalVersion>false</IncludeSourceRevisionInInformationalVersion>` +
> `<EnableSourceLink>false</EnableSourceLink>`
> **只关前两条是不够的**：SDK 默认 `EnableSourceLink=true`，会把当前 git 提交写进 PDB，
> PDB 的内容哈希又进 DLL 的 debug 目录与确定性 MVID。TransparentHer 就只关了第一条、
> 以为修好了，一提交才发现产物还是变。

## 4. 第二条硬约束：不许扩大可达范围

> **无障碍层绝不能扩大可达范围。**（noexistence CHANGELOG 复盘标题原文）

无障碍层的语义是「把本来能看到/能操作的东西，用朗读与键盘**等价地**呈现」，
**不是**「顺手加功能」。三个仓库里由这条推出的具体规则：

| 规则 | 理由 | 后果 |
|---|---|---|
| **限时选择的倒计时只能拉长，不能取消** | 到点会走这一批最后一条的 `ToNumber`，也就是「什么都不做」的沉默分支 | 取消 = **删掉一个剧情分支** |
| **`RevealableText` 必须同时满足「收到开始打印事件」+「面板确实可见」** | 该控件是复用的，文本会在面板显示前就写入（载入存档 / 加载场景 / 预载剧本） | 否则**在 load 场景念出玩家完全不该听到的内容**（实机已发生） |
| **不可用的选项补丁故意不点** | 游戏把该项标成不可用 | 点它 = 越过游戏自己的分支控制 |
| **剧透闸门** | 无障碍朗读会「读出」视觉上一闪而过的信息 | 必须与正常玩家在同一时刻获得同一信息 |
| **`F4` 剧本跳转默认关闭** | 诊断用热键会让人跳过剧情 | 只在排查时开 |

## 5. 陷阱清单（可直接当 review checklist）

这一节是三个仓库 README「几条踩过的坑」+ CHANGELOG 复盘的合并去重，
**每条都有实机事故背景**。新作开发时逐条对照。

### 5.1 通用（任何一作都会踩）

| # | 陷阱 | 正确做法 |
|---|---|---|
| G1 | **对迭代器方法用 Prefix 返回 false 跳过** → 它返回 `null`，调用方是 `StartCoroutine(...)` | 迭代器方法只能改 `ref` 参数（如 `AutoDestroyAfterTime`） |
| G2 | **Harmony 前缀的参数名必须和运行时一致，不是和反编译结果一致** | 写错名字 → `PatchAll` 抛异常，**其他补丁仍生效**，症状极隐蔽：只有一个功能不工作 |
| G3 | **`Enum.TryParse("0")` 成功但得到 `KeyCode.None`**（数值 0），不是 `Alpha0` | 按键配置项先自己映射单个数字 |
| G4 | **别用 PowerShell 文本 cmdlet 改源码** | `Get-Content -Raw` 在 Windows PowerShell 5.1 下按 ANSI/GBK 读无 BOM 的 UTF-8，中文变乱码。用 `[System.IO.File]::WriteAllText(..., UTF8Encoding($true))` |
| G5 | **`.ps1` 含中文且无 BOM → PowerShell 5.1 按 GBK 解码 → 语法错误** | 构建脚本存 UTF-8 **带 BOM**；或发布脚本**纯 ASCII**（noexistence `release.ps1` 的做法） |
| G6 | **BepInEx 日志是缓冲异步刷盘（约 2 秒一次）** | 用脚本读日志驱动自动化测试时必须等够时间，读到「上一拍」是常态 |
| G7 | **`BepInPlugin` 版本号含字母 → BepInEx 判定 `version is invalid` 并静默跳过整个插件** | 只用纯数字四段（想表达 `0.5.8a` 就写 `0.5.8.1`）；构建脚本里加守卫 |
| G8 | **`BepInPlugin` 版本必须与 `.csproj` 的 `<Version>` 一致** | 构建脚本里校验，不一致直接 exit 1 |
| G9 | **`List.Sort` 比较函数不满足传递性 → 结果任意且不报错** | 严格字典序，不许「近似相等」分支 |
| G10 | **世界坐标 ≠ 屏幕像素**（本作画布世界单位极小） | 先 `RectTransformUtility.WorldToScreenPoint` 换算再分档 |
| G11 | **界面重扫不能定时**（激活按钮后 0.35 秒重扫会撞上场景销毁 → **无 C# 异常的原生崩溃**） | 只扫「下一帧」+ 场景稳定门禁 |
| G12 | **找特定控件别用词边界正则**（`\b(exit\|quit)\b` 对 `ExitButton` / `QuitGame` 两头都错） | 拿实查到的对象名**全等比较** |

### 5.2 IL2CPP 专属（三类「静默失败」，全部不报错）

| # | 陷阱 | 正确做法 |
|---|---|---|
| I1 | **`s.transform is RectTransform` 恒为 `false`，`as Toggle` 恒为 `null`** | Il2CppInterop 给的是包装对象，必须走 `TryCast<T>()`。此坑让 Tab 导航一度扫到 0 个控件 |
| I2 | **托管数组传给原生方法会被拷贝，写不回来**（`rt.GetWorldCorners(managedVector3[])` 坐标恒为 0） | 用 `Il2CppStructArray<Vector3>` |
| I3 | **猜对象名（`GameObject.Find("QTEPanel")`）** | 引用游戏自己的类型 + `FindObjectOfType`。类型引用是**惰性解析**的：游戏改版删掉该类只会让这一个功能停用并记一行日志，不会拖垮整个插件 |

### 5.3 逐作特有（各作的「本作不能照抄上一作」）

| 作 | 陷阱 | 正确做法 |
|---|---|---|
| belfry | **不能学上一作常驻关掉 `EventSystem.sendNavigationEvents`**：《钟塔》自己就在用 EventSystem 选中态（横条导航、面板提交、焦点修正、存档槽 `ISubmitHandler`） | 只在导航模式确实要接管那一下按键时才掐（`ShouldMuteUnitySubmit`） |
| belfry | 标题画面的社交链接条（Steam / 小黑盒 / Bilibili）是噪音，且嵌套同名按钮 | 人工排除名单按**祖先链**匹配（只比自己会漏掉子按钮） |
| transparenther | **`EventSystem.sendNavigationEvents` 应常驻关闭**：游戏自己读 `Input`，全代码无 `SetSelectedGameObject` | 若不关：鼠标点过的按钮会在按空格推进剧情时**被重复点击** |
| transparenther / belfry | 限时选择的倒计时音效固定 8 秒，不随拉长的倒计时变长 | 文档里如实说明，不要假装同步 |
| noexistence | Naninovel 面板靠 `CanvasGroup` 显隐：`alpha = 0` 时 `GameObject` 仍 active | 可见性判定必须看 `CanvasGroup.alpha`，不能只看 active |

> **结论**：`EventSystem.sendNavigationEvents` 的处理**必须每作单独判定**，
> 判据是「游戏自己有没有用 `SetSelectedGameObject` / 选中态」。
> 两作给出了两个相反的正确答案——这正是「平台层不能无脑复制到引擎行为」的例子。

### P1 · 实机探针（`probe/`）

在写正式插件之前，先做一个**最小探针插件**，把「猜」变成「看」。

产物（照抄 belfry 的目录）：


**探针必须产出三类证据**：

1. **补丁点存在性** → `probe_full_dump.log`：逐个反射确认要挂的方法名与签名真的存在（**belfry 证据 §2「全部补丁点在运行时存在」**）
2. **组件与对象名** → `scene_tree.txt`：`NameAlias` 表与排除名单的**唯一权威依据**
3. **界面视觉事实** → 截图：证明「按钮文字画在图片上、TMP 里没有字」这类判断

**★ 证据的 IP 红线**（`probe/evidence/README.md` 开篇原文）：

> 本目录只放**不含剧本文本**的证据。
>
> 游戏截图与含台词原文的会话日志**故意不入库** —— 画面本身就是游戏美术资源，
> `[朗读]` 日志行就是剧本原文。仓库的「不包含任何游戏资源」必须**字面成立**。

推论（必须遵守）：

- 探针插件**不记录任何台词文本**，只写类型名、方法名、对象名与控件标签
- 需要复核原始日志时，在本机按 README「如何复现分析」重跑，**不提交**
- 这直接约束了 §2.1 里那条 `[朗读]` 诊断日志：它是**本机排查用**的，
  产出物（`LogOutput.log`）**不得入库**
- 因此 `probe/evidence/` 里只允许放 `scene_tree.txt` 与 `probe_full_dump.log` 这类
  「类型/方法/对象名」级别的转储

**纪律**（`probe/evidence/README.md` 的写法）：

- 证据文件与结论**一起入库**，结论要写「哪台机器、什么时间、什么版本」
- 结论是**断言式**的：「BepInEx 能挂进游戏」「全部补丁点在运行时存在」「标题菜单是纯图片按钮，且带社交链接噪音」

### P5 · 构建与打包

**构建脚本流程**（`mod/build.ps1`，照抄骨架）：

```
1/5  检查游戏目录（找不到 <Game>.exe 就 exit 1，提示用 -GameDir 指定）
2/5  获取 BepInEx（本机 dl\ 缓存 → 跨仓库缓存 CacheDir → 联网下载）
3/5  获取 nvdaControllerClient.dll（x64）
4/5  编译 + ★发布前守卫
5/5  组装 package\
```

**★发布前守卫（三条，必须保留）**：

```powershell
# (1) BepInPlugin 版本号必须是合法 System.Version
[System.Version]::TryParse($pluginVer, [ref]$parsed)   # 否则 BepInEx 静默跳过整个插件
```

**组装规则**：

- `package\` 里**保留自产说明文件**（`安装说明.md` / `常见问题.md`），其余全部重建
  → 说明文件是手写的，不能被构建冲掉

### P6 · 发布

**发布包 = 一个压缩包 + 文档 + licenses，没有安装程序。**

IL2CPP 路线的 `release.ps1` 额外步骤与红线：

- 叠一层**打过补丁的** `Il2CppInterop.Runtime.dll`（上游 PR #277）
- **不打包** `BepInEx\interop` 与 `unity-libs`（首次运行时按本机游戏自动生成，不该由我们分发）
- **不打包** `BepInEx\config\<guid>.cfg`（玩家自己的配置）
- 打包后**自检条目分隔符**：

```powershell
# 绝不要用 Compress-Archive！
# Windows PowerShell 5.1 会委托给 .NET Framework 的 ZipFile.CreateFromDirectory，
# 它用 Path.DirectorySeparatorChar 生成条目名 → 每个条目都是 "BepInEx\core\x.dll"。
# ZIP 规范要求 '/'，Windows 资源管理器 / 7-Zip 甚至 Python 都容忍反斜杠，
# 但 Linux/macOS 的 unzip 不容忍：会解出一堆名字里带反斜杠的平铺文件。
# 用 tools\makezip.ps1 手工构造条目，分隔符恒为 '/'。
```

**版本方案**（`CHANGELOG.md` 顶部固定两节）：

```markdown
## 版本方案          ← 表格：形式 / 含义
## 版本清单          ← 表格：版本 / 日期 / 要点
```

规则：**纯数字四段**（`0.1.0.1`）；`v0.x.y` 是现行官方序列，用 **annotated tag**；
`v1.0.0` 的目标是「**功能完整且经实机验证稳定**」。

**CHANGELOG 条目格式**（照抄这个详略程度）：

```markdown
## 0.1.0.1 — 修复「重读」在快进与选项上的三个漏洞
### 1. 有配音的行没有进缓冲区（静默 bug，反馈里没提到）
### 2. 选项播报绕过了缓冲区

```

要点：**每个修改单独一节，说明「现象 → 后果为什么严重 → 怎么修的」**；
复盘类内容单独成节（noexistence 的 `## 复盘：三类 IL2CPP「静默失败」` 直接变成了 README 的踩坑清单）。

## 7. 给 AI 协作者的工作方式

三个仓库本身就是「AI 协作开发无障碍补丁」的产物（`SisterOtherParanoiaForNVDA` 的描述写着
「vibe coding experiment」）。从三作实践里能提炼出的有效分工：

| 阶段 | 交给 AI 的部分 | 必须人工/AI 实测确认的部分 |
|---|---|---|
| P0 | 资源扫描脚本、剧本统计、反编译摘要 | 「这一作最麻烦的三处」的判断 |
| P1 | 探针插件与转储脚本 | **探针日志的解读**（不许推测） |
| P2 | 平台层拷贝与改名 | 路线判定（Mono/IL2CPP） |
| P3 | `TextProc` 规则、补丁点代码 | **方法名/签名的真伪**（以反编译为准） |
| P4 | 测试问卷、证据整理 | **实机听感**（朗读顺序、打断时机） |
| P5/P6 | 构建/打包脚本 | 版本号守卫、发布包自检 |
| P7 | README / CHANGELOG / 安装说明草稿 | 合规表述、剧透审查 |

**三条铁律**（三作反复验证过的）:

1. **不许猜方法名和对象名** —— 只能来自反编译实查或探针场景树转储。
2. **不许把「没实测」说成「已验证」** —— 未复测就写「**尚未实机复测**」。
3. **别名表每一条都要有依据** —— 在注释里写明来自哪个方法/哪次探针。
